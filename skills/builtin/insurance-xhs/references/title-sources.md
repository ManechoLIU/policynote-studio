# 两份来源的取舍与统一

于 2026-11-16 阅读以下公开资料后整理；链接使用 HEAD，仓库后续可能变化。这是方法整合，不代表安装或启用原仓库的服务。

## 来源一：zhongcao-note-copywriter

- [SKILL.md](https://github.com/beatra-ai/xiaohongshu-copywriter-skill/blob/HEAD/skills/zhongcao-note-copywriter/SKILL.md)
- [references/workflow.md](https://github.com/beatra-ai/xiaohongshu-copywriter-skill/blob/HEAD/skills/zhongcao-note-copywriter/references/workflow.md)

采用：从人群、话题和已有事实选一个角度；默认五条不同标题；短句、具体细节、克制表达；不虚构经历、测评、价格和结论；标题、正文、封面说同一件事；修改时保留已认可的部分。

不移植：Beatra 服务、计费、注册、封面生成、查询和工具调用流程。这些不是标题写作需要的依赖。原文的广告用词筛查应结合适用规则和语境，不将“最、第一”等任何出现都解释为违法。

## 来源二：xhs-content

- [SKILL.md](https://github.com/guzhezao/xhs-content-skill/blob/HEAD/SKILL.md)

采用：读者为什么会点开、看完有什么实际收获；场景代入、信息差、疑问与有依据的反常识；一篇聚焦一点；读者能感知的具体内容；去掉教科书和营销号口吻；质量比凑数量更重要；用真实数据修正主观判断。

不移植：AI日报定位、24小时新闻门槛、特定飞书表格与外部写入、特定作者信源排序、固定评论引导、默认生成全篇、配图与自动推送。原作者13条内容的经验不视为保险领域或所有账号的普遍规律。

原文中的“99%的人不知道”等是标题示例，不是可直接套用的事实；未经证据支持不得借用。其预测分数与加权公式不视为平台算法或可验证的流量预测。

## 合并后的决策

| 两份材料的差异 | 统一做法 |
| --- | --- |
| 内容真实性与强钩子之间的取舍 | 先确定真实可讲的内容，再找点击理由；吸引力不能靠补事实 |
| 泛科普标题与场景标题 | 优先写读者当下会问的具体问题，保留核心搜索词 |
| 强制钩子、禁纯陈述 | 不强制问句或悬念；具体且有价值的陈述也可用 |
| 两份都建议标题20字内 | 作为默认精简目标，不冒充当前平台官方规则 |
| 全篇交付模板与用户只要标题 | 按本次请求交付，标题任务不扩展成完整运营流程 |
| 评分与数量要求 | 内部筛选，默认五条且角度不同；不凑数、不保证效果 |
| 通用写法与明亚项目要求 | 通用技巧用于找表达，明亚要求决定哪些内容可以写 |

## 本次真实反馈

用户认为“体检发现甲状腺、乳腺结节，医疗险该看什么？”等第一版“AI感太强”；在阅读来源后，认可“查出结节，医疗险就没戏了？”等更贴近当事人疑问的写法。

这里确认的是用户的表达偏好，不是点击率验证。后续避免退回泛泛的“几项要求”式标题，也不把这个保险例子的句式强制套到所有行业。

# 五份skill评审与冲突处理

2026-11-17按用户最新要求修正：个人内容的人感必须体现情绪与观点，具体按[情绪与观点](emotion-and-opinion.md)。不编造情绪经历，不代表写稿时不需要情绪；本评审保留对机械频次与虚构亲历的剔除。

本轮评审关注：是否能帮助保险经纪人把真实材料讲清、让开头更值得读、保留本人声音，以及是否与保险风控、课上五步法和当前交付范围冲突。评价针对读到的具体规则，不代表对项目整体或流量效果的认证。

来源链接和再分发边界见[来源与取舍](story-voice-sources.md)。整合后的实际操作见[故事与人话](story-and-voice.md)。

## 逐份看优点和问题

| 来源 | 好的地方 | 不足或不适合保险内容的地方 | 最终处理 |
| --- | --- | --- | --- |
| 文子 xhs-humanize-compliance | 先分清是空泛、没证据、表达费劲还是开头弱；重视作者材料和阅读过程，适配小红书初稿 | 固定问题数量、三点以内和图文页数会让不同题材套同一格式；开头必须兼具话题、观看理由和可信证据，可能塞得太满；“可发”易被当机构审核结论 | 保留具体诊断、材料优先和标题正文一致；不强制结构、页数或开头背书，不出审核通过结论 |
| Humanizer-zh | 保留事实、范围、归因、作者声音与确定程度；不把连接词和标点一律删掉；清楚的句子允许不改 | 主要解决已有文本的语言问题，不负责发现选题价值、补齐故事过程和保险事实核验；光润色不能修好缺证据的稿子 | 用于最后语义核对与语言整理；材料不足先处理资料问题，不把润色当事实验证 |
| viral-content-rewrite | 根据材料选叙事结构；尝试、结果和变化可以推动故事；开头从具体场景或问题进入 | 强制反转、类比、金句、升华和互动会变成另一种模板；部分流量比例、秒数没有可靠依据；为节奏添加情绪可能超出原素材 | 只保留过程推进和阅读主线；不继承流量断言、固定反转或强制口语词，不为了简化删必要条件 |

| mohen | 指出仅换词仍可能空泛，强调具体材料、作者态度和过程；有较详细的问题检查 | 规定第一人称次数、情绪、插叙、标点与emoji密度，容易造假或做作；固定AI味百分比不等于检测结果；有个人体验式风险替换和未核验平台说法；非商用许可不适合直接搬入课程包 | 只作阅读比较，不复制原工具库、词表、脚本和模板；不继承机械频次、自动打分和绕词式处理 |

## 矛盾不能靠“全部都要”解决

| 冲突点 | 统一后的唯一做法 |
| --- | --- |
| 强制故事、亲历与不编经历 | 真实材料决定文体。有真实经过才写真实故事；没有就写答疑、比较或一般解释，不为故事感卡住交付 |
| 强制用“我”与限制二人称 | 不设人称次数。谁实际做了什么就写谁；一般解释可用“你”，本人经历必须有依据 |
| 每篇加情绪、反转与保留事实 | 个人内容要写出可感知的情绪与观点；保留真实感受，也可拟供本人认可的态度表达，不编已发生的心理、动机和对白；不强求反转 |
| 3秒、5秒、10秒、前三行 | 作为作者经验，不作为硬门槛。实际核对开头是否清楚、是否有新信息、是否能接到后文 |
| 强钩子与准确条件 | 吸引力服从保险事实与必要条件；能否投保不等于能赔付，疑问句也不得暗示保证能买 |
| 单一观点、三点以内与复杂比较 | 一篇完成一个阅读任务，保留完成它所需的维度；不限定概念数、三点或段数 |
| 六种新叙事结构与课程六型、五步法 | 新阅读只补表达方法，不重命名课程体系；故事推进放进既有六型，仍用五步法检查理解 |
| 先给答案与故事悬念 | 能回答的事实直接答；过程故事可保留尚未解决的问题，但不故意藏已知答案或编悬念 |
| 短句碎片与自然完整表达 | 按意思断句断段，允许长短变化，不强制一行一句、固定emoji和段落厚薄 |
| 绝对词黑名单与强修辞保留 | 按语境判断是否造成保险承诺、事实夸大或条件遗漏，命中就改主张；不能靠换同义词或“我觉得”保留误导 |
| 强制评论、收藏与隐私保护 | 收尾按问题给下一步，不强制互动；不得邀请公开报告、病史、联系方式或完整保单 |
| 内部评分与用户只要成稿 | 内部做事实和阅读检查，直接交成稿；不输出AI味百分比、流量预测或固定报告 |
| 多平台模板与当前小红书请求 | 只做本次指定的平台和部分，不自动扩成多平台方案、图文拆页或发布 |
| 每个稿件重新研究与局部修改 | 先复用已有资料，只有缺口会影响当前结论才补查；单句改写不启动全账号诊断 |

## 文件分工与优先顺序

用户最新要求和项目AGENTS.md优先，其次是本包事实、风控和隐私要求，再决定表达方式。发现表达建议和这些边界冲突，调整表达，不删除边界。

- `SKILL.md`：识别任务、确定要读哪些文件和交多少内容。
- `title-writing.md`：标题具体写法与单独标题任务的候选数量。
- `emotion-and-opinion.md`：个人内容的情绪、态度与观点标准，避免旧版过度中性。
- `story-and-voice.md`：材料够不够讲故事、过程怎样推进、不同素材状态怎样处理；不新增一套课程骨架。
- `opening-craft.md`：开头的具体入口与接下一句；沿用材料边界。
- `human-speech.md`：用词、句子、段落及作者声音；不补事实。
- `writing-workflow.md`：课上四步、六型、五步法；按素材自然组织。
- `content-risk-rules.md`与`compliance.md`：保险内容与发布边界。

同一规则不再新增一套数值门槛；文件里的标题、故事和开头示例仅为选择，不要求全部使用。审稿与普通创作的输出不同：用户要求审稿才展开问题，用户要成稿就交稿。

## 用现实请求核对决策

| 请求 | 整合后应做什么 | 必须避免 |
| --- | --- | --- |
| 只有“结节也能买的医疗险”，要求故事化 | 先给客观核保或健康告知角度的非故事写法；如要真实案例再明确缺少哪段实际素材 | 虚构患病客户和通过核保的结局，或保留“能买”承诺 |
| 有真实合同对照记录，要求像人讲话 | 保留实际查证过程和本人判断，讲清差异依据 | 强凑悲惨背景、购买结局和客户对白 |
| 只把开头写吸引人一点 | 给材料支持的不同开头，推荐一版并接下一句 | 重新问全套定位、强制多平台交付或生成整篇 |
| 已拍完不能补拍，想换开场 | 从提供的现有原话选；缺原话就索取具体素材或说明只能给剪辑思路 | 将新写的口播冒充原视频内容，编时间码与声画效果 |
| 原稿含“在保证续保期间内”，要求精简 | 保留这个影响结论的期限，用完整口语解释 | 改成“以后都能续”，或以人话为由删条件 |
| 要社群案例拆解 | 原帖完整保留；五步法名称不变，逐块简短说明与模仿示例 | 把新编故事放进原帖、换掉五步名称，或整段标红 |

以上为编辑决策核对，不是发布数据或流量测试。实际效果仍需用户认可的稿件与真实数据来迭代。

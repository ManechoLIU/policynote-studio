## 五步方案工作流（2026-11-23）

新增 `skills/builtin/insurance-note-scheme/`，按「重疾险图文交互与知识库调用图 v3」实现五步闭环：需求单 → 只追问影响事实或方向的关键缺口 → 四套切入角度不同的方案（封面图＋封面文案＋标题＋正文）→ 分项溯源（案例链接/借鉴点/事实状态）→ 选稿改稿并保留原稿与意见。

内容判断仍调用 insurance-xhs：本技能只规定流程、产物结构与版本，不另立写作标准。封面用 `scheme.py cover` 的 PIL 渲染四段模板（无需浏览器），避免 AI 生图把中文写错。事实用项目内 `事实台账.md` 登记来源、版本、状态与失效时间；案例引用只来自案例层索引，没有对标必须写“无直接对标”。

已验证：`init / check / revise / export` 在临时项目跑通，四段封面均渲染为 2160×2880 并逐张目检；空模板被门禁拦下，补齐一套后通过；改稿生成快照 v1 并写入 v2，导出件标“待人工确认”。结构门禁不校验事实真伪，也不代表机构审核。案例层 50 篇目标仍未完成，事实层没有独立产品库，产品与条款需人工核对。

### 首轮实测后的四条修正（2026-11-23）

工作台实测发现：模型读到了新技能，但把“先出方案”理解成单篇选题，跳过需求单与多套，直接做图卡并进入 `skill-xhs-publisher` 预检。据此调整：

- “出方案”但没说数量时，先反问“4 套比较，还是 1 篇成稿”，不自行假设；
- 方案阶段（需求/生成/改稿/导出）禁用发布器，连 `xhs_publish.py check`、`whoami` 也不跑，不问是否保存草稿；
- 封面只允许填 `cover.json` 并跑 `scheme.py cover`（PIL），禁止自写渲染或另造 HTML；`check` 会拦截配置缺失与占位残留；
- 保留单篇模式：只做一套，但需求单、溯源、改稿快照、导出不能省，门禁用 `check --single`。

原始测试产物 `outputs/重疾险等待期图文/` 保留为反例，不作为模板。

### 第二轮实测：逐步停（同日修正）

四条修正后，模型确实先问模式、不再碰发布器、开始用模板；但技能里“一次只做一步、停下等确认”被逐字执行：需求单停一次、正文停一次、封面再停一次，六轮对话仍未交付。第一轮还把模式问题与产品/读者问题捆在一起，用户只答模式后又重复问另外两项。

已改为“一次交付”：五步是内部阶段，除模式问题外同一回合做完；中途只报进度不提问；没跑过 `check` 不发交付消息。第 2 步从“必问”改为“默认优先、只问阻塞项”，问过没答不重复问。

同日又发现工作台 codex 沙箱不允许 Playwright 启动浏览器，封面必然渲染失败。已把封面改为 `assets/covers/cover.json` + `scripts/cover_render.py`（PIL，1080×1440），不再依赖浏览器；并新增 `scheme.py build --input content.json`，一份 JSON 一次写完四套、渲染封面并跑门禁，避开 apply_patch 改中文路径的失败。`check` 校验 JSON 占位与每套 PNG。`outputs/重疾险等待期与复效方案/` 四套已全部 PASS，作为成功样例；`outputs/重疾险等待期图文方案/` 是上一轮反例。

另外，`AGENTS.md` 原“多步骤任务先给简短 Plan”被模型当成确认关卡，已改为“说明计划后同一回合执行到底”。
